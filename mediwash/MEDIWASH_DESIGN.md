# Mediwash 重设计

Mediwash 在 Mediary 的分类工作流里负责选片源、比较版本和跟踪处理结果。用户从「华语电影」「国产剧」「动漫 / 儿童」进入，看到该分类采用的评分规则、待确认的替换和实际入库结果。库内精洗、115 候选和 PT 搜种复用同一套分类策略。

## 1. 分类与策略

Mediary 整理规则决定分类和目标路径。Mediwash 的策略范围由「媒体库、媒体类型、Mediary 分类路径」共同确定。当前宿主把 `电影/华语电影/2020-2030`、`电视剧/国产剧/2020-2030` 等路径写在 `category.yaml` 里，电影和剧集树各有自己的分支。用户选 `电影/华语电影` 时可包含所有年份子目录，某个子目录配置了策略时，使用最具体的匹配。分别展示宿主的「未分类」目录、插件尚无法确定分类的条目，以及已确认分类但没有洗版策略的条目。

| 宿主接入 | 实现 |
| --- | --- |
| 当前宿主 | 从工作台导入 Mediary 导出的 `category.yaml`，保存来源和摘要。按媒体库根目录下的已知路径段识别在库源的分类，优先使用源路径。只有条目路径明确代表该源时才使用条目路径。按完整路径段匹配，遇到多个可能归属、目录别名或未知根目录时，显示原因并交用户确认。 |
| 宿主能力完善后 | 使用插件授权的只读接口取得分类树、分批查询分类下的媒体及其源、请求 Mediary 预判候选的整理分类和目标位置。接口应返回分类标识或路径、规则修订和命中依据，便于在整理前复核。 |

现有分类设置接口对 Mediwash 令牌返回 `401`。首版使用显式导入的分类快照，日期和版本在工作台可见。快照更新后展示分类新增、移除和改名，受影响的策略与尚未执行的建议需要重新确认。宿主分类接口能验证实际归属后，可把已确认的路径绑定到稳定标识。 [本机分类配置](/vol1/1000/appdata/mediary/config/category.yaml)

分类策略包含启用的入口、评分方案及修订、最低分差、槽位保留数、允许的动作。PT 毕业分、站点、搜索和下载额度放在 PT 配置内。识别相同作品使用媒体类型、TMDB ID 和剧集的季集编号。决定淘汰哪个文件时，还要比对媒体库、分类、版本槽位与精确的源 ID。同一部电影同时位于「华语电影」和「技术专区 / 蓝光原盘」时，两边分别保留和维护。

## 2. 规则和附件

| 附件 | 用途与兼容要求 |
| --- | --- |
| `symedia权重洗版规则.json` | 导入收藏满分 V5，原生 100 分，包含 DV、HDR、非 DV 非 HDR 三个槽位。电影 75 / 剧集 65 作为该方案的 PT 毕业线预设。在同槽内允许分辨率升级，跨槽及特殊版本按分类保留策略处理。 |
| `mediatidy评分规则.txt` | 可执行 YAML，方案 `ultimate-precision`。原生 1000 分、12 个维度、27 个槽位，文件体积、总码率、视频码率的权重分别为 20、25、25。保留原文件和未知字段，验证音轨、字幕优先级里的字符串及对象混用格式。 |
| `MediaTidy-多版本评分规则_1_.txt` | 用作 27 槽位行为和评分解释的验收说明。该方案启用独立 HFR 槽位时，预设优先归入相应分辨率的 HFR 槽。试跑展示同时命中的条件及选槽依据。自定义规则出现同优先级的重叠且归属不明时，保留已入库版本。 |
| `MediaTidy-本地匹配规则.txt` | 从说明后的 YAML 读取 80 条 `mr`、89 条 `mp`，以及 `groups`、`streaming`、`region`。数字片名绑定、标题替换、长篇剧集拆季都要有测试。10 条 `output_mr` 随原件保存，交给整理命名环节。 |
| `MediaTidy-TMDB覆盖规则.txt` | 从说明后的 YAML 读取 49 条覆盖和 3 条黑名单。展示命中的标题、媒体类型、TMDB ID 和规则来源。覆盖按清洗后的片名、类型及可用年份核对，同名冲突进入人工确认。 |
| `MediaTidy-远程订阅源清单.txt` | Mediwash 同步识别、评分和 TMDB 覆盖三类订阅。清单中的命名、分类、输出名替换归 Mediary 的整理配置管理，工作台可展示其用途及来源。 |

导入先展示文件类型、解析结果、规则差异和兼容性问题，再发布可回退的规则修订。两份说明型 TXT 按 YAML 正文导入，保留原件供核对。用当前 Go 正则引擎复核，80 条 `mr` 中第 32、40、73–76 条无法编译。新版导入应定位到具体规则，允许确认等效表达式，或把该条标为停用并显示影响。远程订阅验证通过后形成待启用修订，失败继续使用上一次通过验证的版本。已有任务保留当时的规则修订以便复查。

候选识别顺序为文件名预处理、明确的本地绑定或覆盖、订阅补充、宿主 TMDB 查询、季集映射。人工确认优先于规则；在同类规则冲突时优先本地，再按订阅设置顺序处理。黑名单对最终匹配结果生效，命中时停止自动执行。季集映射一次完成并记录映射前后的值，连集文件按实际覆盖的集逐一核对。已经入库的条目使用宿主记录的媒体身份，识别规则只提供解释或复核线索。

每个分类选择一套评分方案并保留原生量纲。对同一比较组使用一致的评分基准，区分探测数据和文件名推断。缺少决定性数据时只生成建议。优先用现有 MediaInfo，缓存以源 ID 或文件身份以及探测版本为键，文件变化后重新探测。`unique`、`max_versions` 和 `unmatched` 都纳入实际决策。平分、未达到分差、匹配不到槽位等原因分别展示，避免「未建议升级」被当成「应隔离或删除」。

## 3. 三条洗版流程

| 入口 | 如何生成建议 | 执行条件 |
| --- | --- | --- |
| 库内精洗 | 在已选分类内按作品和季集归组，同槽比较，展示保留版本、候选淘汰源、分项得分及缺失信息。 | 确认前重新读取源列表，核对分类、同槽胜者和实际源 ID。对应作品或单集仍有经过验证的保留版本时，才调用 Mediary 删除对应源。 |
| 115 目录 | 按监控 CID 取候选，识别和探测后，与目标分类的库内同槽比较。结果可为补槽、升级、保留原版、证据不足待核对。 | 尚未入库的候选由 Mediary 确认目标分类。首期允许人工选择分类做试算，计划的整理路径仍由 Mediary 决定。实际入库验证完成后才进入旧源清理。需隔离的候选移入配置的隔离目录。 |
| PT 主动洗版 | 从指定分类找低于毕业分或缺槽的项目，按额度搜索并记录站点失败。种子属性只用于候选排序，下载后的媒体探测用于最终打分。 | 复用 Mediary 的暂缓整理与下载状态。核对季集覆盖、预计整理路径和实际质量，再由 Mediary 整理。若接口只能覆盖原文件而无法先保留旧源，该路线保留到人工整理。 |

三条流程写同一份待确认队列。每条建议带分类、入口、源或候选标识、规则版本、得分依据、目标位置和执行历史。作业状态覆盖预览、待确认、下载、待整理、待验收、可清理、完成和失败。执行前刷新宿主状态，分类、规则或候选发生变化时让建议失效并重新计算。重试先检查宿主实际结果，以作品、季集、分类、候选和动作类型归并重复操作。工作台与定时动作通过事务领取作业、保存进度，避免网页操作覆盖后台结果。

## 4. 工作台

- **分类总览**以 Mediary 分类树作为入口。选中分类立即看到有效策略、媒体范围、待核对数量、最近巡检和「预览此分类」。无明确策略的分类提供设置入口。
- **待确认队列**按分类、入口、状态筛选。详情并排展示保留版和候选版的源位置、槽位、分数、媒体信息来源和下一步动作。
- **115 与 PT 来源**配置监控目录、站点范围、每轮额度和运行状态。每个候选可回到目标分类，修改归属时立即更新适用策略和分数。
- **规则管理**包含导入、对比、启用、回退和双样本试算。试算依次显示命中的识别规则、季集映射、分类依据、版本槽位和分项分数。订阅与本地覆盖放在这里。

## 5. 交付顺序和验收

1. **分类和库内预览。** 沿用现有 Go 插件及两套评分模型，重做分类范围和决策层。导入分类快照和附件规则，建立按分类、源 ID 更新的索引。以华语电影、国产剧、蓝光原盘和动漫儿童分类作样例，验证父子范围、同片跨分类、未知路径、无结果分类和旧策略迁移。先展示拟保留与拟淘汰源，验收精确源复核后接手动库内清理。
2. **115 分类比对。** 接入宿主预判或人工确认的候选分类，验证 115 测试目录的 TMDB 响应、跨季映射、媒体探测待返回和低分隔离。入库回执能核对分类、作品和季集时，再启用自动送整理和后续清理。
3. **后台 PT 作业。** 媒体库逐页或按分类批量查询，分批保存游标和进度。严格限制 PT 搜索并发，对单个站点单独记录超时或证书异常；工作台提交作业后快速返回进度。宿主可行路径为定时动作按批次处理；配置范围超过一次运行时延续上一次游标。验收同一批可恢复、反复点击不会重复提交，且确认新源前保留旧源。

迁移先备份现有策略、规则和队列。旧策略显示「待绑定分类」，原始设置仍可查看；旧待处理项在重新确认分类与源身份之前只供查看。已有规则保留 ID，导入的原始附件作为新的规则修订。首版沿用干跑默认设置，实际写操作按分类显式启用。

验收样本包含 `1917` 数字片名、剧集跨季映射、同名不同年份、TMDB 黑名单、4K HDR 与 4K HFR 重叠、蓝光原盘分类与普通封装共存、同片跨分类、单条请求超时和宿主整理失败。验收记录同时保留原始附件摘要、导入结果和规则修订，方便复跑。
